# 僵尸危机3：枪口、放置格、控制姿态与待执行射击

2026-10-25，本地验证完成，发布状态见后续 `public-deployment.json`。原SWF保持不变；静态源码/原P-code、模型元数据哈希、每个姿态的方向/原始帧/逻辑帧维度及未完成范围见 [来源记录](source-review.json)。本批不代表完整还原目标完成。

`scripts/import-boxhead-gun-positions.py` 从原模型字面量导入16种人物姿态的逐方向、逐帧枪口位置；可用 `--check` 复核。四种玩家材质均使用0.35比例，原 `FillXSIInfo` 转为世界坐标，缺少 `GunPosition_Right` 的空手姿态回退人物脚下。角度先截断到256再按原查表取方向。控制动画保存当前逻辑名称、共享动画身份、浮点帧及实际绘制帧；每回调推进0.32，步行按0/1/2/3/4/3/2/1往返。原PNG仍保留五个不同原始图像，无需重复烘焙八张。

原 `LoadAnimation` 的清理反编译结果漏写了每帧重置局部变量。为避免误把全部帧视为重复第一张，另核对原P-code：`loc142b` 内明确先 `Push undefined / StoreRegister 2`，随后读取已缓存的往返帧；这支持上述八帧时间轴。目标类P-code导出完整；全SWF导出中另一个无关sprite274脚本超时导致进程exit1，未将整轮导出说成全绿。原字节码静态核对也不等同于Flash运行时跟踪。

人物控制先根据移动结果和原武器确定下一逻辑动画，再选枪/开火，最后换动画或推进帧。故选枪后的第一个回调射击仍可能用旧枪口；手动选枪当帧则调用 `FIRE.Renew` 清除按下/松开事件，自动武器仍可读取实际按住状态。不同空手武器共用动画，切别名不会把共享动画归零；开火前 `Update_CurrentFrame` 预更新会冻结本回调的实际绘制帧。站立/行走依据实际位移，按住墙面不能继续播行走。

另从原 `CInput.UpdateKey/IsPressed/IsReleased` 发现，按键事件在冷却期间应暂存，到武器真正读取时才消耗。现在分别保存内部按住、待按下、待松开状态，冷却期间一次点击/手雷松开不丢失，也不在以后重复。手动换枪、断线/过期输入和失焦取消正确清理待执行事件；联机协议原有的“完整短按可跨采样保留”适配继续保留。

油桶、假墙、地雷、遥控包的放置改为枪口所在格 `mChildCount<=1`，XY归格中心但保留枪口Z；稳定空手姿态下即放在脚下。去掉额外的34像素前置、径向避让和静态墙格拒绝。人数、普通/渐隐物体、补给、弹道、活跃特效和尸体参与格内计数，尚未登记的新物体和地板血迹/焦痕不计。仍在登记的活跃特效、尸体不会被视觉历史裁剪误删。物体/弹道/烟雾等按原45度高度投影绘制；枪口闪光独立保存原发射点和两回调显示寿命，射线/火箭也使用对应原枪口，而非人物中心或统一前移20像素。
