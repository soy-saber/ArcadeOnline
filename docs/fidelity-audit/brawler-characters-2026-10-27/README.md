# 疯狂小人战斗：六个人物选择

按用户最新指示，原菜单外观可简化，选图、换人物等对应功能必须提供。本批修复小人战斗按座位固定人物、第五/第六角色无法选用的问题。全部八款仍按[总清单](../../../ALL_GAMES_REPAIR_PLAN.md)继续，不因该功能完成而标记整体完成。

## 行为与依据

准备界面可选择圆球、咖啡杯、茄子、草莓、垃圾桶、桃子，允许多名玩家选择同一人物。选择绑定席位，换地图、刷新/重新连接保留；换座显示该席位已存的人物。进入对局后锁定选择，移动、攻击、掉落场外、复活及完整/增量恢复沿用选择的人物，使用既有原图和该人物属性。

原SWF `games/6232/game.swf` 的frame_42列出六个Fighters类；frame_46的SelectFighter允许同角色，SetColor为重复人物调整颜色。六类构造函数定义各自Weight/Speed/Power和CharacterName。来源文件与SWF哈希、原菜单顺序及构造参数见[静态来源](source-reference.json)，可运行`python scripts/prepare-brawler-character-reference.py`从原AS2导出复现。选择列表沿用现有素材索引顺序，菜单排列外观不作为还原要求。本批未执行原完整Flash游戏，不宣称运行时全等价。

服务端选人数量由适配器声明决定，取消硬编码“四个人物”；泡泡堂和僵尸危机仍限制各自四个人物。角色ID支持字符串和数字，修复数字0被当成未选人物、刷新回显错误的问题；前端动态生成全部选项。小人战斗快照保存四席位选择，并校验选择范围与人物一致，拒绝观战者、对局中或非法编号修改。

## 验证

新增3项规则测试覆盖六人物×四图、同角色、原构造速度、席位权限、5/6号人物及0号内部身份、换图/加入/重连、非法选择和完整/增量恢复。476项默认规则测试、5项部署检查及类型/来源构建通过。

[三身份实际操作](local-brawler.json)使用真实server.js和正常UI/键盘：逐项选择全部六个人物并观察原PNG实际绘制、同角色选择、四图切换、稀疏P1/P4、换座、刷新后0号身份回显、普通移动/攻击、自然走出场地后减命和复活、完整恢复。没有注入位置、生命、库存、得分或结果。[共用功能回归](local-functional.json)验证僵尸人物与全部选项、改键/触屏/暂停/全屏及羽毛球按钮；泡泡堂选人范围/互斥规则由既有规则测试回归。[八款双Chrome键盘](local-keyboard.json)回归正常输入/松键和远端确认。

开发测试最初遇到一次本地随机端口连接拒绝，改用较低测试端口并要求健康检查成功后才打开页面。两处即时断言早于玩家自己的权威快照/UI回显，改为等待自身确认；刷新用例让该页处于前台，并使用50ms状态轮询。未为这些测试调度问题修改游戏机制或生产连接逻辑。

## 剩余范围

选人功能使用现有每人物四张素材，未在本批补齐完整原动作、独立特技/投射物/抓投、原颜色/队伍选择、模式/规则选项、声音、动态场景和相机。这些仍须按原函数与正常对局继续还原。原玩家颜色与同角色区分的完整渲染尚未移植，本批仅提供同角色选择和现有席位颜色提示。最新公网状态以[部署记录](../../../DEPLOYMENT_STATUS.md)与本目录发布证据为准。
