# 僵尸危机：波次、连杀、升级与补给

本批按用户要求保留原游戏过程，菜单/HUD外观可简化，但对应功能必须完整。全目标覆盖八款，见[总清单](../../../ALL_GAMES_REPAIR_PLAN.md)；本批不代表八款或僵尸危机完整还原完成。

## 修复行为

- 波次初始化使用原四档难度；僵尸与恶魔分别维护总剩余、在场数量、上限和倒计时。按原循环构造100级数据，100级后复用FOREVER参数；死亡尸体全部处置后进入下一波，取消旧版额外65回调等待。死亡竞赛内部等级1、倍率200，不运行生存刷怪/衰减。
- 连杀计数与得分倍率分别计时，保留原GetTicks浮点公式和后减边界。原World.LogKill先提升倍率再计分；普通僵尸每五连杀掉补给，恶魔必掉，死亡竞赛人物死亡掉补给，替换旧版15%随机掉落。
- NewWeapon替换库存但保留当前选择，倒地队友也获得武器，复活时再按原规则清空有限弹药。升级按阈值逐项执行，当前武器在控制回调才应用该类升级；换枪后才刷新其弹药上限，队友和其他枪不会被提前补满。已有弹药升级的武器遇到后续同类升级也按原ApplyUpgrade_Weapon重新装满。最后一发后到下一控制回调再切手枪。
- 补给按原格中心登记、同格领取，墙内不生成；先初始化，再执行10×FPS倒计时及末秒透明淡出，取消自定闪烁。固定补给继续按模式10/30秒及原回调边界重现，选择权重使用每名玩家当时实际武器容量。
- 慢速/正常/快速对应12.5/25/50FPS，修正回血、尸体/淡出、AI等待/转身、地雷/遥控包计时、动画和手雷蓄力。原固定回调常量仍保留：初始保护200、复活等待25、保护25/125、近战睡眠10及攻击动画速度中的25不随FPS改写。
- 死亡竞赛地雷等待放置格人物离开后才开始感应；切换状态的当前回调不立即引爆。完整/增量恢复及状态校验包含新增计数、武器容量/版本和补给生命周期。

## 原函数依据

[原函数来源与哈希](original-reference.json)记录原SWF、相关AS2及运行器版本。`prepare-boxhead-progression-reference.py`准备原AVM1对象属性与调用，`trace-boxhead-progression-reference.cjs`在Ruffle 0.6.0-nightly.2026.8.6执行，`collect-boxhead-progression-reference.cjs`收集到[固定对照数据](../../../tests/fixtures/boxhead-progression-as2.json)。

共1,830条实际观察：LEVEL618、INIT30、STEP1080、SPAWN69、WAVE6、DEAD6、REGEN3、NEW1、OBJECT6、TTL3、WEAPON8，覆盖三个FPS、恶魔开关、1至103级、初始化、生成/清场/回调边界、记杀、回血、死亡掉落、物件与补给生命周期、升级补弹/冷却等。它们由10项新单测消费，并非1,830项独立测试。GetTicks浮点值使用1e-10相对容差，离散计数/事件直接对照。

原函数使用受控外部世界、HUD、集合、生成/效果观察器；武器构造由观察替身承接，未运行原完整场景、AI或集合系统。该证据不等于原Flash全引擎或Adobe运行结果。原AddUpgrade中的AVM1宽松调用行为保留在原运行中观察，未按去编译文字擅自改写。

## 正常浏览器验证

使用真实`server.js`和隔离Chrome身份，只通过正常UI、键盘/触屏操作并只读状态，不注入位置、生命、弹药、得分或敌人。

- [自然升级](local-progression.json)：原BOXY图、Intermediate从第10波开始，正常选择已解锁UZI并射杀实际生成敌人；五次击杀到峰值15解锁桶，当前仍为UZI。合作Expert场景分别在三个速度实测：P1选择UZI后100→200并射击到199，P2保持100；P1霰弹枪20→40，P2保持20。400ms手雷蓄力随速度保持实际时间；暂停及完整恢复通过。
- [死亡竞赛](local-deathmatch.json)：正常拾取固定补给、实际五次击杀/死亡/复活、至少五次死亡掉落、固定补给重现、赢家独占胜场和再次准备通过。
- [完整功能](local-functional.json)：四人物/重复选择/18图/稀疏座位/重新加载，三模式/四难度/功能选项/暂停/全屏/改键/触屏取消和羽毛球按钮功能通过。
- [八款键盘](local-keyboard.json)与[僵尸四身份](local-four-player.json)：WASD/方向键混用、释放、焦点与远端确认，以及四人同步/恢复回归通过。

473项默认规则测试、8项原羽毛球测试和5项部署测试、类型检查、来源构建通过。日志与实际截图同目录。首次完整功能回归在暂停→刷新→恢复后立即按J的确认处超时，玩家仍存活、权威状态有效；仅增加被动事件/清键诊断后原操作流程复测通过，未确认根因，也没有为此改动生产输入逻辑。两个早期自然升级驱动因瞄准/走位失败，后续按真实枪口射线修正驱动、保持相同五杀目标后通过；未调整游戏难度或注入状态。

## 剩余范围

完整集合调度/Mapwho插入和删除历史、原枚举次序、复杂AI视线/几何、全部层级和声音时点仍须继续。当前同格多人领取优先最新对象ID，只近似原集合枚举，不证明完整插入历史一致；寻路仍是确定性五层预算而非原3ms时间预算。新状态与当前浏览器回归通过不能替代这些缺口。其他七款仍按总清单推进。具体上线版本以[部署记录](../../../DEPLOYMENT_STATUS.md)及本目录发布证据为准。
