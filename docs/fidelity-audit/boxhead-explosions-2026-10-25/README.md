# 僵尸危机3：强化爆炸、集束弹与手雷过程

基线 `561f0ff`，原作资源 `games/50737/game.swf` 未改写。[来源审阅](source-review.json) 保存SWF、14个AS2类与三个原图的SHA256；运行与发布版本分别按 [本地验证](verification.json) 和 [部署记录](../../../DEPLOYMENT_STATUS.md) 判断。

原 `CThing_Effect_Explosion.Process_Init` 使BigBang/BiggerBang产生2/3个子爆炸：距离一个32像素网格、随机角、同伤害、延迟2～5且子爆炸无强化/集束标记。每个爆炸仍使用原伤害决定的半径和50%/75%距离衰减；不再额外扩大半径或图像。`Process_Delay` 先减再判断，delay2在第三次回调生效。

原 `CThing_Shot_ClusterShell` 产生四扇区弹片，角度±π/8，寿命16～23回调，初始水平速度1.6～3.2像素/回调、竖直16像素/回调；继承父高度、伤害和玩家归属。重力1.92，预测落地时反射并把整个速度向量减半，然后在同帧按反射向量移动；原墙面反弹后两项水平速度均乘0.25，速度足够时才播放原弹跳音。弹片使用现成原图 `Shot.ClusterShell`（8×5），寿命耗尽后排队产生普通爆炸，不递归集束。

原手雷同样恢复蓄力对竖直速度的缩放和反射当帧移动。一次完整快速点按可能在两次服务器采样之间完成；旧枪的按下时间不再被误当作本次蓄力起点。原18帧爆炸按每回调2.5帧，激活即推进，最后一帧保留至下次清理；显示序列2、5、7、10、12、15、17、17，原图217×163、单位缩放。动画、待执行子爆炸、延迟/初始化标记、弹片身份都随完整/增量快照保存。

原地图油桶生命1、构造伤害100；玩家放置的爆炸物保存武器在创建时的伤害，受击时仅更新对象的爆炸强化标记。地图油桶不再被当成150伤害的玩家油桶。地雷和遥控包没有爆炸Affect登记，不会因相邻爆炸错误起爆。平台保留既有玩家伤害归属/友伤、共享大视野及真人联机适配。

新对象下一次集合回调才执行的依据为原 `CThing_Collection.Process` 的for-in，以及 [固定Ruffle版本AVM1 Enumerate实现](https://github.com/ruffle-rs/ruffle/blob/045db00b393aed22a462d29cb6c25efa26be90a0/core/src/avm1/activation.rs#L1047-L1075)：解释器在循环前收集并压入属性名。这是源码推断，未取得Flash运行时同帧跟踪；当前仍按投射物/效果/敌人/物体分阶段，未把整个原对象键顺序与伤害回调队列逐帧移植。地形碰撞仍使用现有阻挡查询，尚未完整恢复Mapwho高度/球体法线及连续碰撞，也未恢复震屏/亮度、枪口模型定位、其他动作/受击/AI及遥控包三回调起爆等待。

[双浏览器过程](results.json) 使用两个独立Chrome上下文。先用16次真实手枪攻击杀死4只原100HP僵尸，再用真实UZI/数字选枪继续杀到44只，正常达到连击45解锁集束与BigBang。实际投掷一次手雷扣1发，另一浏览器观察到4枚原弹片及总计7次爆炸（主爆炸、2次子爆炸、4次弹片爆炸），原图尺寸/无拉伸断言通过；在延迟子爆炸仍活跃时请求完整恢复，核对子对象id、位置、伤害、归属及原定生效tick，不重复初始化或重生弹片。截图：[自然解锁](earned-upgrades.png)、[原弹片/爆炸](native-cluster.png)。

[四人回归](four-player-results.json) 覆盖四席位实际入座、准备、移动/攻击、全屏、暂停恢复、完整/增量同步、离座/换图与再次开局。全部248单测与5部署测试、类型检查及构建来源检查通过。新增规则测试覆盖两级强化、半径/友伤衰减、集束扇区/全部寿命区间、蓄力/快速点按/地面反射/墙面减速、动画、对象伤害/免触发、完整/增量恢复和损坏快照。运行：`npm run test:boxhead:explosions:e2e`。

夹具只安排原100HP敌人、原场景对象和站位，并清理前场景物件；不授予武器/升级、不改击杀/分数、伤害、无敌、弹药、引信或延迟。规则和时间由服务器自然推进，夹具不进发布包。所有浏览器在同一工作机，本地验收不等同公网或跨地区体验；完整游戏还原尚未完成。
