基线 `04a0b41`。本批为本地还原和验收，尚未部署，公网仍按 [部署记录](../../../DEPLOYMENT_STATUS.md) 的 `84c75ae`。原AS2和素材哈希、恢复规则及已确认后续缺口见 [来源审阅](source-review.json)，最终目标范围见 [还原清单](../../../BOXHEAD_RESTORATION_PLAN.md)。

原遥控包 `CThing_Object_ChargePack.Process_Detonate` 把25/10先减再判断，依次1.5、.5、-.5；第三次回调排队创建爆炸，之后的集合回调才执行新效果。恢复这段等待，去掉直接删包爆炸和任意6tick等待。每个拥有者独立触发；同一拥有者可利用原SelectWeapon.Reset重新选中（包括同一个数字键），在还有弹药时继续布置多包。最后一发用完后仍可切回引爆；只在所属炸药都消失后自动回到手枪。放置扣弹，引爆不扣；选择重置开火等待，不补弹。

地雷和遥控包的原动画Clone从0开始，普通回调每次加1/25、起爆回调每次加1，保留原相位与触发帧的普通推进。使用原25×21地雷及28×26遥控包图，在人物前的地面层绘制，不再使用全局tick的统一闪烁。遥控包放置播放原 `Weapon.Mine.Place`，即使格子占用导致失败仍按原顺序播放；每个包开始倒计时时播放一次原引爆音，恢复不重播。

原 `CWorld.Shake` 在已有幅度小于32时加Y30，每次Draw反号减半、长度小于.1归零。按服务器25Hz保存这段状态，镜头和姓名使用同一位移。原亮度是颜色矩阵的RGB各加255×brightness，爆炸设1、每回调减.2，HUD之后绘制；浏览器使用不透明游戏视口上的additive合成，避免误用普通白色透明覆盖导致颜色不同。等待预览不保留静止白帧，正式开局恢复原初始化亮度。浏览器刷新率不会重复推进或重启这些效果。

[真实双人过程](results.json) 先以正常手枪/UZI射击获得56次击杀、自然达到峰值55，解锁遥控炸药；两名真人各放置，P1重选后再放一包，移动离开后触发其两包，P2的包不动。随后P1真正放完剩余八发，切到手枪再切回零弹药遥控包并引爆，最后自动回手枪；P2的包与9发库存保留。合计11次原放置音、10次原引爆音。中途完整恢复核对子包id、拥有者、伤害、动画相位与原定排队tick，倒计时不延长。截图：[多包布置](multiple-owned-packs.png)、[零弹药仍可引爆](last-ammo-detonator.png)。

浏览器确认慢闪两帧、原绘制尺寸、地面层位于人物之前、真实爆炸时权威震屏/亮度状态，并采集加亮前后RGB与HUD像素：RGB满足加255×alpha后钳制，容差1个通道值，HUD不被滤镜修改。这是采样像素/数学操作的验证，不是与Flash整帧像素对齐证明。[集束弹回归](explosions-regression.json) 和 [真实四人回归](four-player-results.json) 继续通过。

[检查结果](verification.json)：262单测、5部署测试、类型检查和构建来源一致。运行 `npm run test:boxhead:objects:e2e`；夹具只安排原100HP敌人、站位和场景物件，不写击杀/升级/库存、无敌、伤害、计时或动画。第一轮恢复断言中的期望动画表达式存在浮点相减问题，已改为括号内经过tick数及1e-12相位容差，倒计时/排队tick仍精确断言；没有延长生产起爆时间适配采样。全部浏览器来自同一Windows工作机。
