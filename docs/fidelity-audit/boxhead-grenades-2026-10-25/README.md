# 原版手雷与集束弹碰撞流程

以 `ad97cdf` 为基线，对照原 `games/50737/game.swf` 中 `CThing_Shot_Grenade`、`CThing_Shot_ClusterShell`、`CMap_Collide.BounceCollide` / `Collide_Mapwho_Height` / `Collide_Map` 及各类物体高度。来源哈希和规则见 [source-review.json](source-review.json)。原 SWF 与素材未修改，完整目标仍按 [还原清单](../../../BOXHEAD_RESTORATION_PLAN.md) 推进。

手雷构造时保留原枪口 XYZ、方向与投掷力度，第一次回调才设置40像素高度、水平 `power*32` 与垂直 `power*16` 初速，然后立即执行第一次物理回调。服务器用 Init 阶段保存待启动的60回调引信和0.1格半径；Init 不占 Mapwho 子物体，也不提前消耗引信。原版的0.25～0.75秒蓄力、松开投掷、选枪Renew与输入去重继续保留。

每次 Normal 先令垂直速度减0.06格；预计高度落到地面以下时，垂直速度取绝对值，低于或等于0.06格则归零，之后三个速度分量均乘0.5，并将当前位置高度置零。接着按原拟议位置查询周围格的碰撞对象：物件高度一格、人物/僵尸1.5格、恶魔1.8格，同时保留物件自身放置高度。只有预计高度严格低于对象顶面才处理圆形推离，父对象被排除。连续处理多个圆形物体时，查询用临时Z随三维推离更新；最后只将XY结果用于碰撞修正，实际垂直速度保持原值。

地图碰撞继续依次尝试完整位置、只移动X、只移动Y。`BounceCollide` 用修正位置相对原拟议位置的方向作法线，按 `v - 2(v·n)n` 反射水平速度，再将两个水平分量乘0.25。最终从原位置移动反射、阻尼后的位移；原拟议位置和修正位置均不是最终落点。碰撞声音以最终三维速度是否超过0.06格判定。圆形墙面/人物的斜向反弹、低抛被挡而高抛越过、墙角反射与原落地阻尼均由同一逻辑处理。

引信最后一次回调仍先运动，再把共享当前位置的爆炸排入后续回调。手雷/弹片进入 Delete 后保留末帧及 Mapwho 占用，下一次处理才移除。集束弹从构造起就是 Normal，保留16～23回调寿命、原高度、0.5格垂直初速与0.05～0.1格水平初速；不会套用普通手雷的40像素/60回调初始化。父ID、方向、半径、力度及 Init/Normal/Delete 阶段均保存在快照中，验证拒绝缺失阶段、错误Init速度、非法力度/半径/寿命等数据。
