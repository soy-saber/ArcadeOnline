# 全游戏修复：小人战斗场景与冰火人机关显示

用户当前目标为“修复所有游戏”，覆盖全部八款；范围和逐款剩余验收见 [总清单](../../../ALL_GAMES_REPAIR_PLAN.md)。原菜单等外观可以简化，比赛原素材、机制和全部对应功能继续保留。本记录是一批显示修复，不能替代全游戏完成验收。

## 小人战斗

原 `games/6232/game.swf` 的 `__Packages/World.as` 构造函数隐藏名称以Fixed、Moving、AI、Boom、SpawnH、Killer开头的MovieClip。旧导入静态精灵时未执行该代码，将碰撞/出生辅助图形一并烘焙，渲染器又绘制了灰/金色碰撞台。

`scripts/prepare-brawler-visible.py`从原XML识别四个场景的62个辅助实例及显示列表生命周期，再直接过滤原SWF二进制对应场景的放置标签；所有非场景标签及保留的首帧标签保存原始字节。导出使用场景首帧；嵌套动画仍可能扩大透明边界，因此按首帧透明包围盒裁剪，使用原首帧可见矢量边界下取整的原点、自然像素尺寸注册。来源/原World哈希、保留非场景标签哈希、删除实例、每图裁剪与注册数据见 [导入记录](../../../public/expanded/assets/brawler/visibility.json)。栅格边缘取整尚不构成Flash逐像素等价。

删除渲染器重复绘制的碰撞台。四图平台/出生点/死亡边界与原有六角色元数据逐项比较未变。背景和人物PNG保留原仓库字节：进一步直接导出未修改的原SWF也观察到与旧仓库的像素差异，不能把差异单独归因于XML回编译；本批改用原二进制过滤并只替换四张场景PNG，避免扩大无关素材变化。

复现：安装JPEXS与Python Pillow，设置FFDEC_JAR后运行 `node scripts/import-expanded-brawler.cjs`；默认只更新场景，`--all`才重导背景/角色。完整重新导入后所有素材/元数据/来源记录逐字节一致，四图碰撞与六人物元数据保持原修复前版本，见 [重建核验](import-repeat.json)。原始SWF保留，分析缓存不发布。原动画场景（屋顶408帧、轰炸机170帧）、移动平台完整时序、原镜头、人物技能/选人/抓投/投射物和音频仍待后续处理。

## 森林冰火人

原来源 `games/fbw_forest/js/init.js` 的Wind与Roman模块使用分组件素材，图集不存在旧渲染器拼出的wind0000/roman0000。

风机恢复118×80原底座、原开关灯、4张可用底座帧和30张风效帧；原动画请求末尾不存在的第5/31帧不作为实际图集帧。按原30FPS播放，关停时使用静态底座/关灯且无风效；风效按原风长、方向和底部中心锚点绘制，并在人物前景层。跷跷板由原底座、平铺横梁、左右镜像端头与前景中心轴组成，取消该机关的普通实色碰撞矩形。

组件绘制使用服务器现有物理姿态，未借本批重写关卡碰撞/承重/旋转。尤其现有跷跷板近似物理、原始多边形安装位置与真实动态承重仍有差异，必须继续按原Box2D与真实路线核对；本批仅证明缺失组件及动画恢复，不证明32关可按原解法通过。

## 验证与限制
